## 1. 개요: `stand` 키프레임 XML 원본

```xml
<key name="stand" qpos="0 0 0.55 1 0 0 0 0.0 0.40 1.25 0.0 -0.40 -1.25"/>
```

Tron1 로봇은 3D 공간을 자유롭게 이동하는 **부유 베이스(Floating-base)** 로봇이므로, 시뮬레이션 상태 벡터 `qpos`는 **[상체 공간 위치 및 회전 (7개)] + [양다리 6개 관절 각도 (6개)] = 총 13개**의 숫자로 구성됩니다.

## 3. 파이썬 제어기 슬라이싱 매핑 원리

파이썬 코드에서 관절 각도와 속도를 읽어올 때의 슬라이싱 규칙입니다:

```python
# 관절 각도 읽기 (13개 중 구동 관절 6개만 슬라이싱)
q_act = data.qpos[7:13]

# 관절 각속도 읽기 (12개 중 구동 관절 6개만 슬라이싱)
v_act = data.qvel[6:12]
```

### 왜 `qpos`는 `[7:13]`이고, `qvel`은 `[6:12]`인가?
- **`qpos` (위치 차원 = 13)**:
  - 자유 관절(`freejoint`)의 3D 자세 표현에 **4차원 쿼터니언($w, x, y, z$)**을 사용하므로 자유 관절에 **7개**가 소모됩니다. ($3 + 4 = 7$)
  - 따라서 구동 관절은 인덱스 **`7`**부터 시작합니다 (`7:13`).
- **`qvel` (속도 차원 = 12)**:
  - 속도는 쿼터니언 미분이 아닌 **3차원 각속도 벡터($\omega_x, \omega_y, \omega_z$)**로 표현되므로 자유 관절에 **6개**만 소모됩니다. ($3 + 3 = 6$)
  - 따라서 구동 관절의 각속도는 인덱스 **`6`**부터 시작합니다 (`6:12`).
